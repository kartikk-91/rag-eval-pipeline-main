# Repository audit — 2026-10-25 (Hindi/Indic corpus refresh)

## Architecture and clean setup

This is a Python 3.12 RAG service. `rag/ingest.py` extracts PDF text and splits it into overlapping character chunks with page/section metadata. `rag/build_index.py` embeds the chunks into Qdrant. `rag/retriever.py` provides dense, Unicode-aware BM25, hybrid, and optional cross-encoder ranking. The API and active evaluation use the same hybrid retrieval path. `rag/generate.py` calls Bedrock only when answer generation is explicitly invoked; local ingestion, indexing, lint, and unit tests do not need AWS credentials. FastAPI, the LangGraph wrapper, and MCP server expose the application. `infra/` contains deployment definitions; no cloud infrastructure was deployed or changed.

Clean Windows PowerShell setup is documented in `README.md`, alongside Linux/macOS commands. Local run uses `.venv`, `pip install -e ".[dev]"`, `scripts/fetch_hindi_indic.py`, `RAG_DATA_DIR`, `QDRANT_PATH`, and `python -m rag.build_index`. The embedding model is fetched from Hugging Face on first use, so the model cache or network access is needed for indexing/retrieval. The local path does not provision AWS or read local AWS credential files. Bedrock settings are configurable with `AWS_REGION` and `BEDROCK_MODEL_ID` and are only relevant for generation.

`scripts/hindi_indic_papers.csv` now contains 48 bibliographic records selected for Hindi coreference and closely related Hindi/Indic NLP: coreference/anaphora, Indic benchmarks and language models, Hindi/Indic QA and retrieval, parsing/POS/NER, machine translation, and code-mixing. Direct primary-source checks support the scope rationale. Important coreference sources include DeepHCoref (Hindi neural coreference), MCECR (manual multilingual event-coreference annotation including Hindi), the Hindi annotation-scheme work, multilingual coreference studies, and Bridge the GAP (South Asian pronominal coreference). Related high-quality resources include IndicNLPSuite, IndicXNLI, IndicNLG, MILU, Indic-QA, IndicIRSuite, Samanantar, MIRACL, and COMI-LINGUA.

Thirty-one rows are marked `verified downloadable`: 2016+ papers whose publisher is verified as the Association for Computational Linguistics and an arXiv item whose record specifies CC-BY 4.0. The ACL Anthology's current copyright FAQ says ACL materials before 2016 use CC BY-NC-SA 3.0 and ACL materials from 2016 onward use CC BY 4.0; it explicitly says this only covers ACL materials, not third-party material ([ACL copyright FAQ](https://aclanthology.org/faq/copyright/)). The fetcher requires the verified publisher/license note and expected source host. It downloads paper PDFs only. Dataset, code, figures, and third-party material may have separate terms; these are not relicensed by the paper PDF license. The other 17 records remain metadata-only or access/license unclear and are not fetched. Of the 31 eligible PDFs, 29 are local and two need a retry from a networked terminal. PDFs are under ignored `data/` working storage and must not be committed unless the specific file's terms independently allow it.

The inclusion of coreference-specific sources is based on primary publisher/source metadata and abstracts, for example [DeepHCoref](https://aclanthology.org/2024.crac-1.7/), [MCECR](https://aclanthology.org/2024.findings-naacl.245/), and the South Asian [Bridge the GAP](https://aclanthology.org/2025.chipsal-1.10/). ACL Anthology hosting alone is not treated as proof that a work is ACL-published: Bridge the GAP is published by ICCL and remains blocked for download until its terms are confirmed.

## Retrieval, answer, and citation failure modes

- The earlier API used English-only dense embeddings, while BM25 discarded Devanagari tokens. The default is now a multilingual embedding model and Unicode-aware BM25, with reciprocal-rank hybrid fusion shared between API and evaluation.
- The earlier answer prompt lacked inline evidence markers, and the API returned source identities without retrieved passage text. Generation now requests sentence-level `[S#]` evidence markers, validates that factual sentences cite available labels, and returns exact retrieved passage text with source/page/chunk metadata.
- Citation-label validation checks marker presence and range, not whether the cited passage semantically entails each claim. A fluent but unsupported claim with a valid marker can still pass. Manual claim-to-passage review or a dedicated entailment/faithfulness evaluator is still needed; do not describe citation format validation as semantic verification.
- Retrieval can still return irrelevant passages. The current retriever has no calibrated relevance threshold, so an answer may be passed to Bedrock whenever hits exist. There is no local Bedrock test in this audit.
- PDF extraction can create spacing artifacts and unpaired surrogates. The matcher tolerates whitespace loss; ingestion now replaces malformed surrogate code points emitted for some diagram glyphs so the embedding tokenizer can process all chunks. The 29 current gold passages have been checked against chunks from their respective PDFs and then scored against actual retrieved text.

## Evaluation and test gaps

The active `evaluation/eval_set.jsonl` contains 29 source-first questions, one per local PDF. `evaluation/build_hindi_indic_eval.py` records the selected source passages and verifies they match chunks in their own papers before writing the active set; it never calls a retriever to choose gold evidence. Passage text, not document identity or old chunk IDs, is the gold evidence. Human review of answer correctness and citation entailment remains pending. The set is still small, with only one query per paper, so treat results as an initial baseline and avoid extensive tuning.

The 29-question evaluation was run against a new local index at `qdrant_hindi_indic_research` with collection `hindi_indic_research`, leaving prior ignored indexes untouched. Hybrid retrieval measured recall@10 0.483 and MRR@10 0.245; all 29 passages were reachable by rank 100. A paired comparison on the same questions found BM25 alone at recall@10 0.828 and MRR@10 0.538, versus hybrid at 0.483 and 0.245; both improved over dense-only on this set. These source-first questions are abstract-focused and lexical overlap can favor BM25, so this comparison is diagnostic, not sufficient reason to replace the serving retriever. Add manually rewritten queries and more questions per paper, then compare with paired intervals before changing defaults. Evaluate answer citations against actual retrieved passage contents; marker syntax alone does not establish entailment. Rebuild the index after adding papers or changing the embedding model/chunking. CI runs lint and unit tests; old vector snapshots, chunk IDs, robustness questions, and Bengali-era baselines are retained only as legacy artifacts, not active gates.
