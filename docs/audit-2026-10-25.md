# Repository audit — 2026-10-25 (Hindi/Indic corpus refresh)

## Architecture and clean setup

This is a Python 3.12 RAG service. `rag/ingest.py` extracts PDF text and splits it into overlapping tokenizer-aware chunks with page/section metadata. `rag/build_index.py` embeds the chunks into Qdrant. `rag/retriever.py` provides dense BGE, Unicode-aware BM25, hybrid, and optional cross-encoder ranking. The browser exposes BM25, dense, hybrid, and same-query side-by-side comparison; offline evaluation remains the source of aggregate benchmark scores. `rag/generate.py` calls Bedrock only when answer generation is explicitly invoked; local ingestion, indexing, lint, and unit tests do not need AWS credentials. FastAPI, the LangGraph wrapper, and MCP server expose the application. `infra/` contains deployment definitions; no cloud infrastructure was deployed or changed.

Clean Windows PowerShell setup is documented in `README.md`, alongside Linux/macOS commands. Local run uses `.venv`, `pip install -e ".[dev]"`, `scripts/fetch_hindi_indic.py`, `RAG_DATA_DIR`, `QDRANT_PATH`, and `python -m rag.build_index`. The embedding model is fetched from Hugging Face on first use, so the model cache or network access is needed for indexing/retrieval. The local path does not provision AWS or read local AWS credential files. Bedrock settings are configurable with `AWS_REGION` and `BEDROCK_MODEL_ID` and are only relevant for generation.

## Corpus audit and source quality

The original 39 Bengali-era PDFs were removed at the user's explicit request; no backup was retained. The old source manifest and evaluation artifacts are historical and cannot be treated as current corpus labels or results. The local corpus now has 45 PDFs and the active source-first evaluation has 45 unique questions. The current v5 local index contains 2,608 chunks, and v2-v4 index directories are preserved. Historical 29-paper scores and the earlier three-question smoke test do not describe this corpus.

`scripts/hindi_indic_papers.csv` now contains 59 bibliographic records selected for Hindi coreference and closely related Hindi/Indic NLP: coreference/anaphora, Indic benchmarks and language models, Hindi/Indic QA and retrieval, parsing/POS/NER, machine translation, and code-mixing. Direct primary-source checks support the scope rationale. Important coreference sources include DeepHCoref (Hindi neural coreference), MCECR (manual multilingual event-coreference annotation including Hindi), the Hindi annotation-scheme work, multilingual coreference studies, and Bridge the GAP (South Asian pronominal coreference). Related high-quality resources include IndicNLPSuite, IndicXNLI, IndicNLG, MILU, Indic-QA, IndicIRSuite, Samanantar, MIRACL, and COMI-LINGUA.

Forty-five rows are marked `verified downloadable`: 42 ACL-published papers with CC-BY 4.0 terms verified from ACL policy and publisher metadata, plus three ELRA PDFs whose first pages explicitly state CC-BY-NC-4.0. These three are limited to local noncommercial research and must not be redistributed. The ACL Anthology's current copyright FAQ says ACL materials before 2016 use CC BY-NC-SA 3.0 and ACL materials from 2016 onward use CC BY 4.0; it explicitly says this only covers ACL materials, not third-party material ([ACL copyright FAQ](https://aclanthology.org/faq/copyright/)). The fetcher requires the verified publisher/license note and expected source host. It downloads paper PDFs only. Dataset, code, figures, and third-party material may have separate terms; these are not relicensed by the paper PDF license. The other 14 records remain metadata-only or access/license unclear and are not fetched. All 45 eligible PDFs are present locally in ignored `data/hindi_indic/`. Do not commit PDFs unless the specific file terms independently permit redistribution.

The inclusion of coreference-specific sources is based on primary publisher/source metadata and abstracts, for example [DeepHCoref](https://aclanthology.org/2024.crac-1.7/), [MCECR](https://aclanthology.org/2024.findings-naacl.245/), and the South Asian [Bridge the GAP](https://aclanthology.org/2025.chipsal-1.10/). ACL Anthology hosting alone is not treated as proof that a work is ACL-published: Bridge the GAP is published by ICCL and remains blocked for download until its terms are confirmed.

## Retrieval, answer, and citation failure modes

- The earlier pipeline used the Sentence Transformers config's 128-token limit while indexing passages near 500 tokens, so vector embeddings silently omitted much of each chunk. The v4 experiment introduced the same Hugging Face tokenizer for splitting and encoding, a 480-token chunk size with 128-token overlap, a validated 512-token input window, and build-time length validation. V4 used multilingual MiniLM and did not retrieve a gold passage in the top 10 on this English-query set. V5 uses the FPA-specified BGE-small English retrieval model; v2-v4 indexes are preserved as historical snapshots and v5 has a separate Qdrant path and collection. The current English-only test does not establish Hindi-language retrieval quality.
- The earlier answer prompt lacked inline evidence markers, and the API returned source identities without retrieved passage text. Generation now requests sentence-level `[S#]` evidence markers, validates that factual sentences cite available labels, and returns exact retrieved passage text with source/page/chunk metadata.
- Citation-label validation checks marker presence and range, not whether the cited passage semantically entails each claim. A fluent but unsupported claim with a valid marker can still pass. Manual claim-to-passage review or a dedicated entailment/faithfulness evaluator is still needed; do not describe citation format validation as semantic verification.
- Retrieval can still return irrelevant passages. The current retriever has no calibrated relevance threshold, so an answer may be passed to Bedrock whenever hits exist. There is no local Bedrock test in this audit.
- PDF extraction can create spacing artifacts and unpaired surrogates. The matcher tolerates whitespace loss; ingestion now replaces malformed surrogate code points emitted for some diagram glyphs so the embedding tokenizer can process all chunks. All 45 active gold passages have been checked against chunks from their respective PDFs; the next retrieval run will score them against the new index.

## Evaluation and test gaps

The active `evaluation/eval_set.jsonl` contains 45 unique source-first questions, one per local PDF. `evaluation/build_hindi_indic_eval.py` records the selected source passages and verifies they match chunks in their own papers before writing the active set; it never calls a retriever to choose gold evidence. Passage text, not document identity or old chunk IDs, is the gold evidence. Human review of answer correctness and citation entailment remains pending. The set is still small, with only one query per paper, so treat results as an initial baseline and avoid extensive tuning.

The previous 29-question metrics are superseded. The 45-question source-first evaluation is regenerated against the token-aware chunker and matched to its source PDFs. The active baseline in `evaluation/hindi_indic_baseline.json` reports the v5 results: hybrid R@10 0.956 / nDCG@10 0.618; dense and BM25 R@10 0.822 each. Paired hybrid-minus-dense intervals exclude zero for R@10 and nDCG@10, but not MRR; BM25 is much faster on the measured machine. These metrics do not measure answer faithfulness. The overlap diagnostic shows mean informative-term overlap 0.211 with selected gold evidence and 0.467 with the best non-gold same-paper chunk, so the current abstract-heavy set is vulnerable to wording bias. Add naturally rewritten queries and more questions per paper, then compare with paired intervals before changing defaults. Evaluate answer citations against the exact retrieved passage text; marker syntax or returning the right source alone does not establish entailment. Rebuild the index after adding papers or changing the embedding model/chunking. CI runs lint and unit tests; old vector snapshots, chunk IDs, robustness questions, and Bengali-era baselines are retained only as legacy artifacts, not active gates.

## Remaining constraints and next steps

2. Compare retrieval strategies only on the same reviewed query set, and keep the current BM25/hybrid comparison diagnostic until then.
3. Keep paper PDFs local unless their individual terms permit redistribution.
4. Do not deploy infrastructure, create AWS resources, enable paid services, or make Bedrock calls as part of this refresh.
