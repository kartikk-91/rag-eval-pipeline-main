# Repository audit — 2026-10-25 (Hindi/Indic corpus refresh)

## Architecture and clean setup

This is a Python 3.12 RAG service. `rag/ingest.py` extracts PDF text and splits it into overlapping character chunks with page/section metadata. `rag/build_index.py` embeds the chunks into Qdrant. `rag/retriever.py` provides dense, Unicode-aware BM25, hybrid, and optional cross-encoder ranking. The API and active evaluation use the same hybrid retrieval path. `rag/generate.py` calls Bedrock only when answer generation is explicitly invoked; local ingestion, indexing, lint, and unit tests do not need AWS credentials. FastAPI, the LangGraph wrapper, and MCP server expose the application. `infra/` contains deployment definitions; no cloud infrastructure was deployed or changed.

Clean Windows PowerShell setup is documented in `README.md`, alongside Linux/macOS commands. Local run uses `.venv`, `pip install -e ".[dev]"`, `scripts/fetch_hindi_indic.py`, `RAG_DATA_DIR`, `QDRANT_PATH`, and `python -m rag.build_index`. The embedding model is fetched from Hugging Face on first use, so the model cache or network access is needed for indexing/retrieval. The local path does not provision AWS or read local AWS credential files. Bedrock settings are configurable with `AWS_REGION` and `BEDROCK_MODEL_ID` and are only relevant for generation.

## Retrieval, answer, and citation failure modes

- The earlier API used English-only dense embeddings, while BM25 discarded Devanagari tokens. The default is now a multilingual embedding model and Unicode-aware BM25, with reciprocal-rank hybrid fusion shared between API and evaluation.
- The earlier answer prompt lacked inline evidence markers, and the API returned source identities without retrieved passage text. Generation now requests sentence-level `[S#]` evidence markers, validates that factual sentences cite available labels, and returns exact retrieved passage text with source/page/chunk metadata.
- Citation-label validation checks marker presence and range, not whether the cited passage semantically entails each claim. A fluent but unsupported claim with a valid marker can still pass. Manual claim-to-passage review or a dedicated entailment/faithfulness evaluator is still needed; do not describe citation format validation as semantic verification.
- Retrieval can still return irrelevant passages. The current retriever has no calibrated relevance threshold, so an answer may be passed to Bedrock whenever hits exist. There is no local Bedrock test in this audit.
- PDF extraction can create spacing artifacts and unpaired surrogates. The matcher tolerates whitespace loss; ingestion now replaces malformed surrogate code points emitted for some diagram glyphs so the embedding tokenizer can process all chunks. All 45 active gold passages have been checked against chunks from their respective PDFs; the next retrieval run will score them against the new index.

## Evaluation and test gaps

The active `evaluation/eval_set.jsonl` contains 45 unique source-first questions, one per local PDF. `evaluation/build_hindi_indic_eval.py` records the selected source passages and verifies they match chunks in their own papers before writing the active set; it never calls a retriever to choose gold evidence. Passage text, not document identity or old chunk IDs, is the gold evidence. Human review of answer correctness and citation entailment remains pending. The set is still small, with only one query per paper, so treat results as an initial baseline and avoid extensive tuning.

The previous 29-question metrics are superseded. The current 45-question evaluation was regenerated from the expanded PDFs and run against the 1,686-chunk showcase index. Current retrieval values are in `evaluation/hindi_indic_baseline.json`; they do not measure answer faithfulness. These source-first questions are abstract-focused and lexical overlap can favor BM25, so this comparison is diagnostic, not sufficient reason to replace the serving retriever. Add manually rewritten queries and more questions per paper, then compare with paired intervals before changing defaults. Evaluate answer citations against actual retrieved passage contents; marker syntax alone does not establish entailment. Rebuild the index after adding papers or changing the embedding model/chunking. CI runs lint and unit tests; old vector snapshots, chunk IDs, robustness questions, and Bengali-era baselines are retained only as legacy artifacts, not active gates.
